九起事故、六条铁律：企业上 AI Agent 的安全清单

2026-10-10 Luna 约 2 分钟
AI监管AI与企业经营

Photo by Nathan Thomas on Pexels

安全公司 GitGuardian 复盘了 2025 年 5 月到 2026 年 7 月间的九起真实事故，提炼出六条防护措施。正在把 AI Agent 接进业务的公司，不妨拿它当一份现成的自查清单。

九起事故被归到三个攻击面上：运行环境（Host）、身份凭证（Identity）、Agent 自身的行为。作者有一个反直觉的结论：这六条措施，没有一条能防住提示词注入——原话是「None of them prevent prompt injection」。防护的目标不是让 Agent 不被骗，而是被骗之后，损失能被摁住在可控范围。

六条措施分别是：把 Agent 关进沙箱；凭证按最小权限发放；锁住配置，不让 Agent 或外人随手改；记录每一次调用；接手一个工作区之前，先扫描里面有没有裸露的密钥；对敏感操作默认拒绝、逐项放行。每一条单看都不新鲜，新的是把它们当成 Agent 时代的默认配置，而不是出了事再补。

同一天的两条新闻，给这份清单做了正反两面的注脚。反面：一位开发者用一句用户看不见的隐藏指令，测试了 10 家公司的 13 个模型、8 个可评估的 Agent，前后发送约 800 次请求，结果其中 4 个 Agent 每次都照做不误。正面：The Verge 报道，OpenAI 在 DevDay 上发布 Agent 产品 Dots 时，把「隐私新标准」当作主打承诺；而竞争对手 Meta 的 Muse 虽已修补零日漏洞，仍被质疑可被 Meta 访问虚拟机中的数据——这款产品日活已有 60 万。厂商的承诺是一回事，落到清单上的控制措施是另一回事。

对财务和内控背景的读者，这份清单翻译过来就是三句老话：权限最小化、全程留痕、敏感操作要复核。Agent 换了一代工具，内控的底层逻辑没变——变的只是，这次要在它动手之前就把规矩立好。
